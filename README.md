### Задание 1

Опишите основные преимущества использования масштабирования методами:

- активный master-сервер и пассивный репликационный slave-сервер; 
- master-сервер и несколько slave-серверов;


*Дайте ответ в свободной форме.*

Основные преимущества масштабирования с использованием активного master-сервера и пассивного репликационного slave-сервера:

- Повышение отказоустойчивости системы: если основной (master) сервер выходит из строя, его может заменить репликационный slave.
- Снижение риска потери данных и увеличение надежности: slave-сервер хранит актуальную копию базы данных.

Преимущества масштабирования с помощью master-сервера и нескольких slave-серверов:

- Увеличение производительности системы за счет распределения нагрузки при чтении между несколькими slave-серверами.
- Улучшение отказоустойчивости: при выходе одного из slave-серверов остальные продолжают обслуживать запросы, поддерживая доступность данных.
- Возможность масштабируемого горизонтального роста инфраструктуры: добавление новых slave-серверов при росте нагрузки без изменения кода приложения.
- Улучшение скорости обработки запросов, особенно при большом количестве операций чтения: мастер обрабатывает только записи, slaves — чтение.

Активный master и пассивный slave:

- Отказоустойчивость: Slave-сервер может взять на себя функцию основного в случае критического сбоя master-сервера, сокращая простой системы.
- Безопасность данных: Репликация помогает минимизировать риск потери данных из-за аппаратных или программных ошибок master-сервера.
- Быстрое восстановление: Переключение на slave-сервер происходит быстрее, чем восстановление данных с резервной копии.

Master и несколько slave-серверов:

- Масштабирование чтения: Запросы на чтение распределяются между slave-серверами, уменьшая нагрузку на master и ускоряя обработку запросов пользователей.
- Гибкость инфраструктуры: При необходимости можно добавить дополнительные slave-серверы для баланса нагрузки без изменения архитектуры.
- Высокая доступность: Если один или несколько slave-серверов становятся недоступны, остальные продолжают работу, что увеличивает доступность сервиса.
- Резервирование при сбоях: Серверы могут быть размещены в разных географических локациях для защиты от локальных аварий.

### Задание 2


Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц: 

- пользователи, 
- книги, 
- магазины (столбцы произвольно). 

Опишите принципы построения системы и их разграничение или разбивку между базами данных.

*Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.* 

В текущем задании будут использоваться следующие типы разбивки данных.
### Разграничения
Пользователи
- Горизонтальный шардинг: по диапазону user_id (например, 1–1 000 000, 1 000 001–2 000 000).
- Вертикальный шард: часто используемые поля (id, username, email) на одном сервере, остальные (password_hash, bio, settings) на другом.

Книги

- Горизонтальный шард: по диапазону category_id (например, 1–100 книг на шард 1, 101–200 на шард 2 и так далее).
- Вертикальный шард: основные атрибуты (id, title, author) отдельно от описаний и изображений.
Магазины

- Горизонтальный шард: по region_id или диапазону store_id.
- Вертикальный шард: основные реквизиты (имя, адрес, регион) и отдельная таблица для дополнительных параметров (акции, отзывы).

### Режимы работы серверов
- Все шардированные серверы работают в режиме мастер-серверов своего диапазона, каждая группа может иметь пассивный слейв-сервер для обеспечения отказоустойчивости.
- Горизонтальные шарды независимы и обслуживают только свои диапазоны.
- Вертикальные шарды требуют координации между серверами для сбора полного профиля/объекта.
